# S3.1e Keep the RAM copy across container restarts: requirements

Measured on the A1 (22 Nov 2026, after S3.1d): restart to healthy was 25.0 s and 46.2 s. The `/ram` tmpfs belongs to the container (compose `tmpfs:`), so every restart copies 1.7 GB from the `/data` Docker volume again. The block volume reads 133 MB/s uncached (11 GB/s from page cache), so the time before uvicorn starts ranges from 4.5 s (cached) to 28 s (not cached). Shutdown also waits up to 5 s for the maintenance thread (`_Maintenance.stop` joins with `timeout=5.0`) when a pin check is in flight. Gate: restart to healthy under 20 s, every byte served still SHA-256 checked once per boot against the same manifests and pins as today.

- R1 Host tmpfs. `deploy/oracle/setup.sh` (idempotent, like the swapfile step): ensure `/etc/fstab` has `tmpfs /var/lib/chapter-and-verse-ram tmpfs size=3g,mode=0700,uid=1000,gid=1000,nosuid,nodev,noexec 0 0`, create the directory and mount it if not mounted. `deploy/compose.yml`: replace the `/ram` tmpfs entry with a bind mount of `/var/lib/chapter-and-verse-ram` at `/ram` (read-write; the container stays `read_only: true` otherwise, user 1000). Keep `/tmp` tmpfs. Document in `deploy/README.md` (layout, memory: the copy now persists until host reboot or dataset change; the 3 GB counts against host RAM as before).
- R2 Boot order in `deploy/entrypoint.sh`:
  1. If `fetch_artefacts.py --data-dir "$RAM_DIR" --marker-only` passes (the RAM copy is of the wanted source) and `fetch_artefacts.py --data-dir "$RAM_DIR" --verify-only` passes: serve from RAM. No read of `/data`.
  2. Else if `--marker-only` passes on `/data`: empty `$RAM_DIR` (remove its contents, not the mount point), then `--copy-to "$RAM_DIR" --data-dir "$DATA_DIR"`; on success serve from RAM.
  3. Else the existing full path unchanged (full fetch on `/data`, then empty RAM, `cp -R` and `--verify-only`, then volume fallback).
  Log one line to stderr saying which path was taken. Passes `sh -n`.
- R3 Parallel verify. `deploy/fetch_artefacts.py` `verify_all` (used by `--verify-only` and the normal fast path): hash files in parallel on a thread pool (`ARTEFACTS_WORKERS`, default `min(os.cpu_count() or 1, 8)` for verify), keeping the rule that a nested manifest is verified before its entries are expanded and trusted. Same results and exit codes as today.
- R4 Shutdown. `engine/chapterverse/app.py` `_Maintenance.stop`: join with `timeout=0.5` (the thread is a daemon; an in-flight pin check is abandoned, pins unchanged). No other change in `app.py`.
- R5 Tests: `--verify-only` parallel gives the same result as before on the fixture layouts in `tests/test_fetch_marker.py` and `tests/test_fetch_copy.py` (pass, tampered file, tampered nested manifest); a test that `--marker-only` on a RAM-like copy with the marker passes and fails after the marker is changed. A test for the entrypoint is not required; instead write `$CV_SCRATCH/s3-host-ram/entrypoint_sim.sh`-free reasoning in your summary of each path.
