# Sealed held-out run on Modal: requirements

The pre-registered held-out run of the Qwen judge on Groq (method `reports/heldout-qwen-method.md`, commit a491e8d) is closed on 20 Nov 2026 as "halted for capacity": the live site and the run share the Groq account's 200,000 tokens a day. At the halt, 47 of 274 Groq calls had been fetched and cached; no row was scored and no outcome was viewed (the runner scores only in its final pass). The user approved replacing it with a new pre-registered run on Modal, in a separate Modal workspace (`dpl015`), with the measured preset exactly.

- R1 `reports/heldout-qwen-groq-halted.md`: a short record of the halted attempt: method commit a491e8d, started 2026-11-19T10:36:48Z, 47 of 274 Groq calls cached, 0 Cloudflare calls, halted 2026-11-20 for capacity, no row scored or viewed, cache kept unopened in the scratch directory. Plain voice.
- R2 `reports/heldout-qwen-modal-method.md`: the new pre-registered method, written before any Modal call. Same battery, seal hash, 346 rows, enrichment layer from the seal commit, `JudgedVerifier` + `STRICT_FIGURES`, `qwen27-ar4` short prompt, counting copied from `scripts/run_battery.py` as in the Groq method (read `reports/heldout-qwen-method.md` and reuse its wording where it still holds). Detector name `qwen27-ar4-modal`. Every call goes to the Modal SGLang server deployed from `deploy/modal/serve.py` in workspace `dpl015`, with the measured preset unchanged (all sampling fields sent, thinking off). No routing rule, no overflow provider. The battery is run once for this detector; the result is reported whatever it is; it is reported next to the DeBERTa held-out figures and states that the Groq attempt was halted unscored.
- R3 `eval/heldout_modal.py`: a runner for R2 that imports the shared pieces from `eval/judge_gate.py` without modifying that file (it is the code of record for the halted attempt). It refuses to send any call without `--method-commit <sha>`; reads `MODAL_URL` and `MODAL_API_KEY` from the environment at call time; caches replies by prompt sha under `$CV_SCRATCH/heldout-modal/`; writes once-per-detector markers there; enforces a dollar cap `--max-usd` (default 3.00) using the ledger's Modal cost model; and prints the summary as the Groq runner does.
- R4 `tests/test_eval_heldout_modal.py`: offline tests with a fake chat: refuses without a method commit; caches; cost cap stops the run; counting matches the Groq runner's on the same fake verdicts.
- R5 `uv run python -m eval.heldout_modal --dry` counts calls and estimated cost offline and sends nothing.
