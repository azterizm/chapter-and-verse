# S3.1c Parallel store decompression: requirements

Profiled inside the A1 container (22 Nov 2026), `open_store('/ram')` takes 7.3 s: 5.2 s in one `ZstdDecompressionReader.read` stream over all 430,222 frames on one core, 1.5 s in `b"".join(chunks)` (a full copy of 3.84 GB), 0.25 s hashing (SHA-256 runs at 1.4 GB/s, not the cost). The SymSpell dictionary load (7.7 s, pure Python) runs on a thread beside it but cannot overlap because the decode loop holds the GIL between chunks. Restart to healthy is 24.8 s; the gate is under 20 s.

- R1 `chapterverse/store/reader.py` `_decompress_all`: decompress the frames in parallel into one preallocated buffer of exactly `self._ustart[-1]` bytes, with no full-size join or copy. Split the frame index range into K contiguous ranges (K = `min(os.cpu_count() or 1, 8)`, overridable by env `STORE_DECOMPRESS_THREADS` for tests), balanced by compressed bytes using `self._cstart`. Each thread has its own `ZstdDecompressor(dict_data=self._dictionary)` and writes its range into its slice of the buffer (for example `stream_reader` over a memoryview of that range's compressed bytes with `read_across_frames=True` and `readinto`, or per-frame `decompress` into the slice). Choose the variant that measures fastest on the real store and keeps the GIL mostly released; report both numbers. Check each range's output length against `self._ustart` and raise `StoreLoadError` on any mismatch (fail closed, as today).
- R2 Same behaviour for callers. `_read` and every other user of `self._decompressed` return `bytes` exactly as today (wrap slices with `bytes(...)` if the buffer is a bytearray or memoryview). The buffer must not be writable through any public path. Grep the engine for every use of `_decompressed` and keep each identical.
- R3 Identity test: on the fixture store with K = 1, 2, 3 and 7 threads, the decompressed buffer's SHA-256 equals the old single-stream implementation's (keep the old one as a private test helper or compute it in the test with `stream_reader`), and `_read` / `load_provision` results for every coordinate are identical. A truncated or corrupted `text.zst` still raises `StoreLoadError`.
- R4 Measure on this Mac with the real store (`artefacts/store`): `open_store` seconds and peak RSS before and after (K = default), and `build_runtime` time with `SYMSPELL_DICT=artefacts/symspell/dictionary.txt` (the dictionary thread now overlapping), using a script under your scratch dir. Report the SHA-256 of the full decompressed buffer before and after (must be equal).
