# S4.4 Retrieval inside a named instrument (F1) and range citations (F10): requirements

Reproduced 24 Nov (no model): "What is the limitation period for bringing a claim in tort under the Limitation Act 1980?" routes `ROUTE_BOUNDED ('uk/ukpga/1980/58',)`. The Act's windows exceed the premise cap (`PREMISE_BUDGET_TOKENS` 1500, `MAX_PROMPT_WINDOWS` 8), so `select_windows` ranks windows by query-term matches in the window TEXT only (headings ignored) and sends s.14A(5), s.21(2), s.25(1), s.28A(1), s.32(1), s.33(6A), Sch 3 para 8, Sch 4. s.2 ("Time limit for actions founded on tort") is never sent. Slice 3 dense and RRF run only for discovery (no citation), so they do not help here. Second case: "Quote the exact statutory wording of section 172(1)(a) to (d) of the Companies Act 2006." binds `uk/ukpga/2006/46/s172/1/a` only.

Facts you can rely on (checked): the router's concept index (`legal_rag_router.concepts.ConceptIndex`, loaded as the router's concepts) has one document per section-level provision; doc ids `0 .. first_instrument_doc-1` are provisions, and every instrument's provision docs are ONE contiguous id range (0 re-entries over 69,925 instruments; a full scan of `doc(i)` takes about 4 s on the Mac). Postings (`postings(term)`) list doc ids ascending, so a range filter is a bisect. The dense store (`chapterverse.dense.store.BinaryInt8Store`) rows are the same doc ids (row i = concept doc i).

- R1 Instrument ranges: a small module `engine/chapterverse/bound_rank.py` builds `instrument coordinate -> (first_doc, end_doc)` from the concept index once (scan, or faster if you find a way; log the seconds). It runs on a background thread started in `app.build_runtime` after the router is loaded; until it is ready (or if it fails), selection falls back to today's behaviour, logged once. Memory: report the map's size.
- R2 Restricted ranking: `rank_sections(query, instrument, ...) -> list[(coordinate, score)]` over that instrument's provision docs only: BM25F with the router's own field weights and parameters (import them from `legal_rag_router.discovery`'s policy, `DEFAULT_DISCOVERY`; do not copy numbers) computed from the public `ConceptIndex` API (`postings`, `document_frequency`, `field_lengths`, `average_lengths`, `terms` for the query, thesaurus expansion if the router uses it); and, when the pipeline has a dense retriever, exact dense scores of the query embedding against those rows only (dequantised int8 dot product, the same scoring as the store's rescore stage; add a store method `score_rows(query_vec, start, end)` in `dense/store.py`). Fuse with RRF, k from the discovery config (`rrf_k`, same value discovery uses). Without dense, BM25F alone. Deterministic ties (doc id).
- R3 Use in selection: in `pipeline._bounded`, when a bound coordinate is a whole instrument (4 or 5 parts) and its windows do not all fit, pick windows by section rank: walk sections best first and add that section's windows (the window with the best lexical highlight first, then the rest of the section in order) while they fit the budget and the window cap, keeping `highlight` trimming as `select_windows` does. Record the strategy as a new value `"ranked"` in `Selection.strategy` and in the outcome. Bound sections and subsections (not whole instruments) keep today's selection unchanged. Keep `select_windows` itself for the fallback.
- R4 Range citations (F10): when the query names a range or list of sibling paragraphs or subsections next to the bound citation, bind all of them: "(a) to (d)", "(a)-(d)", "(a) - (d)", "(a) and (b)", "(a), (b) and (c)", "(1) to (3)". Implement as a pure function `expand_siblings(query, coordinate, store) -> list[coordinate]` in `bound_rank.py` that reads the parent's children from the store (in store order) and returns the siblings from the first to the last named label inclusive; anything unclear (labels not siblings, not found, end before start, more than 26) returns `[coordinate]` unchanged. Apply it in `pipeline._read` to each bound coordinate. Route events and receipts show the expanded coordinates.
- R5 Tests (fixture store and a tiny fake concept index): range map, BM25F restricted ranking order on a fixture instrument, RRF with a fake dense scorer, `score_rows` equals the store's rescore for the same rows, selection walks sections in rank order and respects budget and cap, fallback before the range map is ready, `expand_siblings` cases (each pattern above, unclear cases unchanged), and a pipeline test that a range query binds all siblings.
