# S3.1b Restart under 20 s: requirements

Measured on the A1 after S3.1 (22 Nov 2026), `docker compose restart` to healthy took 44.4 s:
- 5 s: `fetch_artefacts.py` hashes all of `/data` (1.7 GB) although the marker already matches;
- 4 s: copy to `/ram` and hash the copy again (`--verify-only`);
- 7.8 s: data open (store, router index, concept index);
- 8.2 s: `load_dictionary` of the shipped SymSpell file (2.7 s on the Mac);
- 0.5 s: spaCy;
- 17.8 s: the startup provider pin check, run in the lifespan before readiness (groq 1 s, cloudflare 16.8 s, one after the other);
- the startup retention purge also runs before readiness.
Gate: restart to healthy under 20 s on the A1, with no loss of verification (every byte served is hash-checked once per boot, fail closed) and identical answers.

- R1 Pin check off the readiness path. In `app._lifespan`, do not await the startup pin check or purge; schedule both as immediate first runs on the maintenance thread (then on their intervals as today). In `pin_check`, check the providers concurrently (a small thread pool, one thread per provider), then call `apply_checks` once with all results. A failed or inconclusive check still leaves the pins as they were. Document in the module docstring that until the first check finishes the providers keep their configured initial state; state in your summary what that initial state is (pinned or not, prefill on or off) and confirm it equals the state between daily checks.
- R2 Hash once per boot. `deploy/entrypoint.sh` and `deploy/fetch_artefacts.py`: add `fetch_artefacts.py --marker-only` that exits 0 only when `DATA_DIR` holds the manifests of the wanted source (same check `already_verified` does on the marker and manifest hashes) without hashing data files, else 3. Entrypoint: if `--marker-only` passes and a RAM dir exists, copy `/data` to RAM and run full `--verify-only` on the RAM copy; if that passes, serve from RAM. In every other case run the full fetch on `/data` (downloads and repairs, fail closed as today), then the RAM copy and verify as today, falling back to volume paths. So the bytes served are always fully verified once. Tests in `tests/test_build.py` or a new `tests/test_fetch_marker.py` for `--marker-only` (match, missing marker, other revision). Entrypoint passes `sh -n`.
- R3 Dictionary load. Profile `chapterverse.normalise.load_dictionary` (or wherever it lives) on the real file with `uv run python -m cProfile -s cumtime` on a script in your scratch dir. If most time is Python per-line parsing overhead outside `SymSpell.create_dictionary_entry`, make a faster loader that builds an identical `SymSpell` object. If the time is inside `create_dictionary_entry` (generating deletes), do not reimplement SymSpell internals; instead, in `build_runtime`, load the dictionary on a thread started before the data open and join it after, and measure. Either way add a test that the new loader gives identical results: for 2,000 words sampled from the dictionary with one edit applied (fixed seed), `lookup(..., Verbosity.CLOSEST, max_edit_distance=2)` and `lookup_compound` return identical suggestions to the old path. No pickle.
- R4 Measure on this Mac with the real store and `SYMSPELL_DICT=artefacts/symspell/dictionary.txt` (reuse `$CV_SCRATCH/s3-dict-artefact/measure_s3.py`, copied into your scratch dir): start to healthy before and after, and the dictionary seconds. Report.
