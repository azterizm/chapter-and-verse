# S5.3 Clarify ranking for citation-less questions: requirements

Observed 24 to 25 Nov: "How long do I have to sue in tort?" offers TULRCA 1992 s.22 and s.219 ahead of Limitation Act 1980 s.2 when dense is off; with dense on (live) s.2 came first. Candidate order comes from `discover_step` in `engine/chapterverse/discovery.py` (router BM25 `router.discover`, then RRF with dense hits, optional ColBERT rerank). The router contract stays: a citation-less question is never auto-bound; we only change the ORDER of the offered candidates.

- R1 Everyday battery `batteries/everyday/everyday.jsonl` from `everyday.md` in this spec dir: `id`, `question`, `gold` (list of store coordinates; any gold or a descendant counts). Resolve labels to coordinates with the router and store and verify each gold exists and is in force; if a gold looks wrong do not change it, add `"note": "CHECK: ..."` and report it. All rows are dev (no seal).
- R2 Measurement `eval/clarify_rank.py`: `uv run python -m eval.clarify_rank [--dense-dir DIR] [--out DIR]` runs each everyday question through `Pipeline.run` exactly as `eval/discovery_gate.py` builds it (import its builder, do not copy) and reads the `clarify` event's candidates; reports per row the rank of the first gold (or miss), hit@1, hit@3, hit@10, MRR, with dense on and off. Also run the concept battery DEV split the same way (find how `eval/discovery_gate.py` selects rows; add a `--split dev` option to it if it only runs test, without changing its default output) and report hand hit@10 and MRR (baseline 0.929 and 0.750 with dense).
- R3 Diagnose first, then change: for E01 and every everyday miss or rank above 3, write in `$CV_SCRATCH/s5-clarify-rank/diagnosis.md` the BM25 rank, dense rank and fused rank of the gold and of the candidates above it. Then evaluate candidate-order signals that do not bind: (a) an instrument prior from the router's data (for example instrument in-degree: how many other instruments' text cites the instrument, or how often the router battery names it; build it offline from data the repo or the router data already has, as a small artefact under `artefacts/` with a build script, or computed at startup if it takes under 2 s), (b) a section prior (a section of a general Act over a section of a niche one when BM25 scores tie or are close), (c) RRF weights between BM25 and dense. Keep only a change that improves the everyday set AND leaves concept dev hit@10 and MRR not worse (with dense; also report without dense). If none qualifies, change nothing in the engine and report the numbers.
- R4 Wiring: if a prior artefact is needed at runtime, load it where the other discovery inputs are loaded (`app.py` / `pipeline.py`: minimal, optional, absent artefact means today's order exactly), and document it in `docs/ARCHITECTURE.md` (two lines). Never change routing for questions with a citation, never auto-bind, never drop a candidate today's order would show; only reorder within the top 50 pool.
- R5 Tests in `tests/test_discovery.py` (or a new `tests/test_clarify_rank.py`): absent prior gives today's order exactly; the prior reorders a synthetic tie; nothing binds. Fixture data only.
- R6 Final numbers in the summary: everyday hit@1/3/10 and MRR before and after, concept dev before and after, with dense on and off.
