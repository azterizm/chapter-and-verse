# S3.1d Copy and verify in one pass: requirements

A1 restart after S3.1c (22 Nov 2026) is 20.2 to 20.9 s; gate under 20 s. Phases: 3.5 s Docker stop and start, 4.5 s entrypoint (`fetch_artefacts.py --marker-only`, `cp -R /data/. /ram/`, then `--verify-only` on `/ram`, which reads 1.7 GB again and hashes files one after another), 12.8 s app startup (dictionary bound). SHA-256 runs at 1.4 GB/s per core on the A1; it has 4 cores.

- R1 `deploy/fetch_artefacts.py --copy-to DIR` (with `--data-dir SRC`): requires the `--marker-only` condition on SRC (else exit 3, copying nothing). Copies the whole SRC tree to DIR, exactly what `cp -R SRC/. DIR/` copies today (every file, including unlisted ones and the marker), preserving relative paths. Every file listed in the manifests (main, extra, nested, as `verify_all` expands them) is hashed while it is copied, from the same bytes that are written (one read of the source), and checked against its expected size and SHA-256. Files copy in parallel on a thread pool (`ARTEFACTS_WORKERS`, default `min(os.cpu_count(), 8)` for this mode). Large files are copied in chunks of 4 MiB or more. Any mismatch, missing listed file or I/O error: exit 1. The nested manifests must themselves be verified before their entries are trusted (same order rule as `verify_all`). Standard library only, as the rest of the script.
- R2 `deploy/entrypoint.sh`: in the RAM fast path replace `cp -R` plus `--verify-only` with one `--copy-to "$RAM_DIR" --data-dir "$DATA_DIR"`; on any non-zero exit fall through to the existing full path (full fetch on `/data`, then `cp -R` and `--verify-only` on RAM, then volume fallback), unchanged. Passes `sh -n`.
- R3 Tests (`tests/test_fetch_marker.py` or a new `tests/test_fetch_copy.py`): on a fixture data dir with a store manifest, an extra manifest with a nested manifest, and one unlisted file: `--copy-to` gives a byte-identical tree (every file, including the unlisted one); a tampered listed file gives exit 1; a wrong marker gives exit 3 with nothing copied; a tampered nested manifest gives exit 1.
- R4 Measure on this Mac: copy+verify of `artefacts/store` laid out as a data dir is not possible without the router manifests, so build a test layout under your scratch dir from the real store files (store files and `corpus-manifest.json`, plus `symspell/`) with a marker you write, and time old (`cp -R` then `--verify-only`) against new (`--copy-to`). Report both.
