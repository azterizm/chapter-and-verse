# S3.3b Embed on Modal: requirements

The bake-off (specs/s3-dense-bakeoff) embedded on the Mac CPU at about 40 docs/s: too slow for the full corpus (1,322,050 docs, about 9 h). The user approved Modal (production workspace) for embedding. You write the code; the orchestrator runs every Modal command (you must never run `modal`). bge-small and e5-small pool embeddings are already cached in `$CV_SCRATCH/s3-dense-bakeoff/cache/` (`<model>.npy`, rows in the order of `pool_doc_ids.json`); gte-small is missing.

- R1 `engine/chapterverse/dense/embed.py`: `OnnxEmbedder` gains `providers: Sequence[str] = ("CPUExecutionProvider",)` passed to `onnxruntime.InferenceSession`, and a property `active_providers` (the session's `get_providers()`). The module must import with only `numpy`, `tokenizers`, `onnxruntime` and the standard library (no `chapterverse` imports at module level), so it can be shipped alone into a Modal image. Keep CPU behaviour and tests identical.
- R2 `deploy/modal/embed.py`, Modal app `cv-embed`:
  - Image: `modal.Image.debian_slim(python_version="3.12").pip_install("onnxruntime-gpu==1.32.0", "tokenizers==0.23.3", "numpy==2.5.5")`, plus `engine/chapterverse/dense/embed.py` added as a local file (imported as a plain module) and the three bake-off model dirs from `artefacts/models/` (`bge-small-en-v1.5`, `e5-small-v2`, `gte-small`) added as local dirs, with `models-manifest.json`.
  - A `modal.cls` `Embedder` on `gpu="L4"`, `max_containers=4`, `timeout=1800`, `scaledown_window=60`. `@modal.enter` does nothing heavy; method `embed(model: str, kind: Literal["doc","query"], texts: list[str]) -> bytes` loads (and caches per container) the model with `providers=["CUDAExecutionProvider", "CPUExecutionProvider"]`, verifies the model files' sha256 against the manifest (reuse `load_model` logic), RAISES if `CUDAExecutionProvider` is not in `active_providers` (never silently run on CPU and bill GPU time), and returns float32 `np.save` bytes of shape (len(texts), dim). Batch size 256 inside.
  - A `@app.local_entrypoint()` `main(model: str, out: str, doc_ids: str = "", limit: int = 0, shard: int = 4096, max_usd: float = 2.0, store: str = "artefacts/store", data_root: str = "~/Code/legal-rag-router/data")`. It opens the store and the router's concept index locally, builds doc texts with `chapterverse.dense.doctext` for either the ids in the `doc_ids` JSON file (same format as `pool_doc_ids.json`) or all docs in doc-id order (optionally the first `limit`), splits them into shards, and calls `Embedder().embed.map(...)` preserving order (`order_outputs=True`). Writes `<out>/<model>.npy` (float32, rows in doc order; for the full corpus write with `np.lib.format.open_memmap`, never holding all texts and vectors twice in memory) and `<out>/<model>.doc_ids.json` when `doc_ids` is given, plus `<out>/<model>.meta.json` (model, revision and file sha256 from the manifest, count, dim, providers, seconds, estimated USD).
  - Spend guard: before starting, estimate seconds as `count / 1500` docs per second per container, call `deploy/modal/ledger.py` `check("L4", estimate * containers)` and refuse if over `max_usd`; after, `record("dense-embed <model>", "L4", wall_seconds * containers_used, note)`. Print the estimate and the recorded spend.
  - Text generation must not be the bottleneck: generate shards lazily (a generator feeding `.map`) so GPU work starts at once.
- R3 Bake-off accepts cache files made by R2 for missing models: `eval/dense_bakeoff.py` gains `--cache DIR` (default the current cache dir) and `--models` list; it embeds on CPU only the models with no cache file, and it embeds QUERIES on CPU always (production embeds queries on the A1 CPU). Note in the report that pool vectors for gte-small (or any model cached from R2) came from the GPU build. Dev split only, as before.
- R4 Tests without Modal: the shard and order logic of the local entrypoint, factored into a plain function, round-trips with a fake embed function (order preserved, memmap shape, meta written); `embed.py` imports without `chapterverse`.
