# S4.2 Read-only receipt and ledger reader (F6): requirements

Diagnosing a bad live answer needs the stored receipt (Answer Fact Object, table `receipts`, see `deploy/schema.sql` and `AnswerFactObject` in `contracts.py`) and the provider quota ledger (`provider_quota`). Broad database access was refused by the permission classifier, so we need one narrow, read-only, auditable tool. The user sees answer ids shortened to 12 hex characters (for example `e18112ae91e4`).

- R1 `scripts/receipt.py ANSWER_ID_PREFIX`: prefix is 8 to 64 lowercase hex characters, else exit 2 with a usage line. Reads the DSN from `DATABASE_URL` or else the file `~/.config/chapter-and-verse/database_url` (use `chapterverse.config.read_secret` if it fits); never prints, logs or echoes the DSN or any part of it, including in error messages (print the exception class only). Opens one psycopg connection with `options='-c default_transaction_read_only=on'`, runs only parameterised SELECTs: `SELECT answer_id, fact, created_at FROM receipts WHERE answer_id LIKE %s ORDER BY created_at DESC LIMIT 5` with `prefix || '%'`. 0 matches: exit 1 "no receipt". More than one: list ids and times, exit 1.
- R2 Output for one receipt, plain text (and `--json` for the raw fact): answer id, created_at UTC, mode, route status, bound coordinates, policy hash, corpus id; passages table (passage id, coordinate, span if any, version date); sentences (index, verdict, passage ids, reasons, rollbacks, text); provider calls (each `ProviderCall` field: provider, purpose, model, latency, tokens, outcome or error kind, as present in the contract); totals: calls per provider and purpose, summed latency per purpose, rollbacks.
- R3 `scripts/receipt.py --quota YYYY-MM-DD [--minutes HH:MM-HH:MM]`: read-only SELECT over `provider_quota` for that UTC day: day rows per provider, and minute rows in the optional window (requests, tokens, rate_limited, errors).
- R4 `--file PATH` reads a fact JSON from disk instead of the database (same output), for tests and offline use.
- R5 Tests `tests/test_receipt_tool.py`: argument validation, prefix to LIKE parameter, read-only connection options passed (fake connect), output on a fixture fact built with `AnswerFactObject` (round trip through `to_dict`), DSN never appears in stdout or stderr on success or on a connect error (inject a fake DSN string and assert), `--quota` SQL is a SELECT with parameters. No real database in tests.
- R6 Usage goes in the module docstring. Do not edit docs.
