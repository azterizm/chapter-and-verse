# S3.1 Ship the spelling dictionary: requirements

Today every engine start on the A1 builds the SymSpell dictionary from the text store: 157 to 175 s of downtime per deploy or restart. The dictionary is a pure function of the store, so build it once at publish time, publish it with a hash, verify it at boot, and load it from the file. Also, `pii.py` reads its vocabulary only from `<repo>/artefacts/symspell/dictionary.txt`, which exists on the Mac but not in the container: production PII fallback behaves differently from what the tests measured. Runtime behaviour must never depend on files in the source tree.

- R1 Build. `build/symspell_dict.py` (through `symspell_build.build_dictionary`) writes `dictionary.txt` and a manifest named `symspell-manifest.json` (rename from `manifest.json`; the `-manifest.json` suffix is what `deploy/fetch_artefacts.py` expands as a nested manifest). The manifest holds `files` (`dictionary.txt` with `sha256` and `size`), `counts.terms`, `kind`, `format_version`, `snapshot`, and the store's `corpus_id` (from `chapterverse.store.manifest.corpus_id`) when built from a `TextStore`. Output is byte-identical across runs on the same store (sorted terms, sorted JSON keys).
- R2 Publish. `build/publish_dataset.py` takes `--symspell DIR` (default `artefacts/symspell`). It checks `dictionary.txt` against `symspell-manifest.json` (hash and size), checks the manifest's `snapshot` and `corpus_id` equal the store's, and refuses (PublishError) otherwise. It uploads the manifest and dictionary as `symspell/symspell-manifest.json` and `symspell/dictionary.txt` in the same single commit as the store and router dirs, and lists them in the dry-run output and the dataset card. A dry run makes no network call (unchanged).
- R3 Fetch. `deploy/fetch_artefacts.py`: `DEFAULT_EXTRAS` gains `symspell/symspell-manifest.json`. Every listed file is verified exactly like the others (fail closed). Update the docstring and `deploy/README.md` (env table and rollback row: rolling artefacts back to a dataset revision without `symspell/` needs `EXTRA_MANIFESTS=index/index-manifest.json,concepts/concepts-manifest.json`).
- R4 Entrypoint. `deploy/entrypoint.sh`: after choosing `STORE_DIR` (RAM or volume), if `$STORE_DIR/symspell/dictionary.txt` is a file, export `SYMSPELL_DICT` to it; otherwise leave it unset and print one warning line to stderr. POSIX sh, `set -eu` kept, passes `sh -n` and `shellcheck` if installed.
- R5 Runtime load. `app._load_slice2_dictionary(env, store)`: if `SYMSPELL_DICT` names a file, read the sibling `symspell-manifest.json`; load the file only when that manifest exists, its `corpus_id` equals the open store's corpus id, and the file's SHA-256 equals the manifest's. Otherwise log a warning with the reason and build from the store (the existing fallback, kept). Log one line: source (`file` or `store`), term count, seconds. No words or paths of user data in logs.
- R6 One vocabulary. Remove the repo-path lookups from `pii._load_symspell_words` and `pipeline.Pipeline._get_dictionary`. `mask_pii` takes an optional `vocabulary: frozenset[str] | None` (default None keeps today's PROPN-only behaviour when no dictionary is available); `Pipeline` builds it once from its SymSpell dictionary (the lowercase keys of `dictionary.words`) and passes it on every `mask_pii` call. `_get_dictionary` keeps `SYMSPELL_DICT` and the build-from-concepts fallback, no repo path. Existing PII tests that relied on the repo dictionary must pass the vocabulary explicitly (build it from `artefacts/symspell/dictionary.txt` inside the test, skipping if absent).
- R7 Tests. (a) Build a dictionary from the fixture store into tmp, then `build_runtime` with `SYMSPELL_DICT` set to it: log says `file`, a misspelled uncited query gets a corrections notice. (b) Same with a tampered dictionary byte and with a wrong `corpus_id`: runtime falls back to `store`, still works. (c) No `SYMSPELL_DICT`: `store` path still works (existing test). (d) `fetch_artefacts` verifies a nested `symspell/symspell-manifest.json` and fails on a tampered dictionary. (e) publish dry run lists the two symspell files and refuses a mismatched `corpus_id`. (f) No module under `engine/` references `artefacts/symspell` (grep test).
- R8 Measure on this Mac, real store (`STORE_DIR=artefacts/store`, `LEGAL_DATA_ROOT=~/Code/legal-rag-router/data`): rebuild `artefacts/symspell` with `uv run python build/symspell_dict.py --store-dir artefacts/store --out artefacts/symspell` (report seconds, terms, sha256), then start uvicorn from a script under `$CV_SCRATCH/s3-dict-artefact/` with `SYMSPELL_DICT=artefacts/symspell/dictionary.txt` and time process start to 200 on `/api/health`; report the dictionary load seconds from the log line, total seconds and RSS. If loading the file takes over 5 s on the Mac, profile it (`uv run python -m cProfile` on a script) and report where the time goes; do not switch to pickle.
