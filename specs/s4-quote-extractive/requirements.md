# S4.5 Exact-wording requests answered from the store (F11): requirements

"Quote the exact statutory wording of section 172(1)(a) to (d) of the Companies Act 2006." went to the model, which paraphrased about its inputs and abstained twice. A request for the wording itself needs no model: the store holds the text. Serving it extractively is instant, deterministic and cannot misquote. The orchestrator has added `"quote_requested"` to `ExtractiveReason` in `contracts.py` (do not edit `contracts.py`).

- R1 Quote intent: new module `engine/chapterverse/intent.py`, `is_quote_request(query) -> bool`, deterministic, case-insensitive: "quote", "verbatim", "exact wording", "exact words", "exact text", "word for word", "full text of", "wording of", "what are the words of", "text of section". Keep the phrases in one constant. Not intent: "quota", "quoted company", "quoted price", "quotation marks"; add tests for each.
- R2 Answer: in `pipeline._bounded`, when `is_quote_request(norm_text)` and every bound coordinate is below instrument level (a section, subsection or paragraph, not a whole instrument), skip selection trimming, the budget notice and generation: emit an `ExtractiveEvent` with reason `"quote_requested"` holding the bound provisions' windows in store order with full text (`highlight` None), at most `MAX_EXTRACTIVE_WINDOWS`; when more exist, add a `NoticeEvent` code `"quote_truncated"` saying how many of how many are shown and that the full text is at the link. Status rules stay: a repealed or not-in-force provision is refused or noticed exactly as today. The receipt has mode `"extractive"`, no provider calls, and does NOT count against the daily cap or global budget. A whole-instrument quote request goes through the normal path.
- R3 Templates: in `templates.py`, wording for the new reason if the engine renders any text for extractive reasons (read how `providers_unavailable` is rendered); in the voice of the site: short, plain ("Statutory text, quoted from legislation.gov.uk."). 
- R4 Web: `web/src/api/events.ts` accepts reason `"quote_requested"` (type and validator); `web/src/text.ts` gets its label and line in the same style as the others: short. Check that the extractive view shows the full text and the citation link for each window; change nothing else in `web/`.
- R5 Tests: `tests/test_intent.py`; a pipeline test with the fixture store that a quote request for a section gives the extractive event with reason `quote_requested`, full window text, no provider call (a rotation that fails the test if called), mode extractive, no daily cap increment; a whole-instrument quote request still generates; web unit test for the validator if web tests exist (`npm run --prefix web test`).
- R6 Gates: `uv run python -m eval.legal_gate --split dev --dense-dir artefacts/dense/index --models-dir artefacts/models` (no row may get worse), `uv run python -m eval.probes_gate --target local` 29/29, `uv run python -m eval.run --out $CV_SCRATCH/s4-quote-extractive/battery` routing identical to before (this change is after routing).
