# S5.4 Web: real-engine mock streams, local real-engine preview, kept smoke test: requirements

The mock streams in `web/mock/streams/` are synthetic and pre-Sprint 4 (old wording; one s.124 answer for every unmatched question). Reviews of the web should use real answers.

- R1 Recorder `web/mock/record_engine.py`: runs a fixed list of questions through the real engine in-process (`chapterverse.app.build_runtime` with an environment copy that has `DATABASE_URL` and every Modal setting removed; Groq and Cloudflare only), and writes each answer's SSE bytes exactly as the server streams them (reuse the engine's own encoder, `encode_sse` or whatever `app.py` uses) to `web/mock/streams/engine/<name>.sse`, plus `engine/index.json` mapping each name to its question, the UTC time and the policy hash. Questions (names): `tort` "What is the limitation period for bringing a claim in tort under the Limitation Act 1980?", `tort-clarify` "How long do I have to sue in tort?", `tort-chosen` "How long do I have to sue in tort? (s.2 Limitation Act 1980)", `quote-172` "Quote the exact statutory wording of section 172(1)(a) to (d) of the Companies Act 2006.", `reject-30` "How long is the short-term right to reject under the Consumer Rights Act 2015?", `era-124` "What is the limit of the compensatory award under the Employment Rights Act 1996?", `not-in-act` "What is the national minimum wage hourly rate under the Employment Rights Act 1996?", `out-of-coverage` a question naming an instrument the store does not hold (pick one from the engine's own out-of-coverage path). A `--only NAME` option and `--pace SECONDS` (default 20) between questions. npm script `mock:record:engine`. You must NOT run it (it calls providers); the orchestrator runs it. Test it with a fake runtime.
- R2 Mock plugin `web/mock/plugin.ts`: when `web/mock/streams/engine/index.json` exists, a query that equals (trimmed, case-insensitive) a recorded question, or contains the scenario keywords listed for it, replays that engine stream; otherwise the existing synthetic scenarios apply unchanged (they test error paths the engine cannot be made to produce). Unmatched questions get `era-124` when present, else the old `answer`. Keep the existing delays logic.
- R3 Real-engine preview: `npm run dev:engine` in `web/` starts Vite with `/api` proxied to `CV_ENGINE` (default `http://127.0.0.1:8000`) and the mock off, no Turnstile site key (the app already skips Turnstile without one). Add a Python entry `scripts/dev_engine.py` that starts the engine for this preview the way the container does (`uvicorn chapterverse.app:app`, one worker) bound to 127.0.0.1 only (refuse any other host), with `DATABASE_URL` and Modal settings removed from the environment, and prints the URL. Find out whether the engine requires the Worker-minted session token on `/api/ask`; if it does, the preview must work without weakening production: a dev-only switch read ONLY by `scripts/dev_engine.py` is acceptable if `app.py` already has such a switch; do NOT add one to `app.py` (report it instead and stop that part). Document both commands in `web/README.md` (short).
- R4 Smoke test kept in the repo: `eval/web_smoke.py` (Playwright via `uv run --no-project --with playwright==1.55.0 python eval/web_smoke.py --base URL --out DIR`), which loads the page with `wait_until="load"`, asks a question from the mock (`--mock`) or from a real engine, waits for the done event in the UI, and saves screenshots at 1280, 768 and 360 px wide in light and dark, and fails on any console CSP violation (`Refused to`), page error, or horizontal overflow. It must import nothing from `chapterverse` (it runs without the project env). Do not run it if Playwright browsers are missing; say so.
- R5 Component tests (vitest, `web/test/dom/`): the clarify Change flow at a phone width (choose a candidate, the turn is replaced in place with the original question kept, "Using ... Change" shows, Change re-opens the choices); mock plugin picks the engine stream for a recorded question and falls back correctly.
