# S3.3e Ship the dense index and model: requirements

Slice 3 passed its gates (`reports/slice3-gates.md`). To run on the A1 the engine needs the dense index (`artefacts/dense/index/`: `dense-manifest.json`, `vectors.i8`, `codes.bin`, `scales.f32`, 545 MB) and the query model (`artefacts/models/bge-small-en-v1.5/`: `onnx/model.onnx`, `tokenizer.json`, `tokenizer_config.json`, `config.json`, `special_tokens_map.json`, `1_Pooling/config.json`, about 128 MB) fetched, verified and loaded exactly like the store and the spelling dictionary (S3.1). The app already loads dense when `DENSE_DIR` and `DENSE_MODEL_DIR` are set (`app.py`, the model verified through `models-manifest.json` by `chapterverse.dense.embed.load_model`). The orchestrator runs the real publish and deploy; you never upload or deploy.

- R1 Publish. `build/publish_dataset.py` gains `--dense DIR` (default `artefacts/dense/index`) and `--models DIR` (default `artefacts/models`) and `--dense-model NAME` (default `bge-small-en-v1.5`). Checks before upload (PublishError on any failure): every dense file against `dense-manifest.json` (sha256, size); the dense manifest's `corpus_id` and `snapshot` equal the store's; the model files against `models-manifest.json`. Uploads, in the same single commit as everything else: `dense/` (the four files) and `models/<name>/...` plus `models/models-manifest.json` restricted to that one model's entry (same format the app reads) plus a standard `models/models-files-manifest.json` (`{"files": {"<path relative to models/>": {"sha256", "size"}}}` covering `models-manifest.json` and every model file) so `deploy/fetch_artefacts.py` can verify them. List them in the dry run and the dataset card (licence of the model: MIT, source repo and revision). Dry run makes no network call.
- R2 Fetch. `deploy/fetch_artefacts.py` `DEFAULT_EXTRAS` gains `dense/dense-manifest.json` and `models/models-files-manifest.json`. Both are verified like the others in every mode (normal, `--verify-only`, `--copy-to`, `--marker-only` marker contents). If `dense-manifest.json` lacks a top-level `files` mapping in the standard format, make the build write it in that format (R4) rather than special-casing the fetcher. Update the docstring and `deploy/README.md` (env table; rollback row: an older dataset revision without `dense/` and `models/` needs `EXTRA_MANIFESTS` set to the older list).
- R3 Entrypoint. `deploy/entrypoint.sh`: after choosing `STORE_DIR`, if `$STORE_DIR/dense/dense-manifest.json` and `$STORE_DIR/models/models-manifest.json` are files, export `DENSE_DIR="$STORE_DIR/dense"` and `DENSE_MODEL_DIR="$STORE_DIR/models"`; otherwise print one warning line and leave them unset (dense off). Passes `sh -n`.
- R4 Index manifest format. Check `build/dense_index.py`'s `dense-manifest.json`: it must have `files` as `{"vectors.i8": {"sha256", "size"}, ...}` (the fetcher's format) and keep the fields the app reads. If it does not, change the builder and the store loader together, with tests, and say so.
- R5 Host RAM. `deploy/oracle/setup.sh`: the host tmpfs grows to `size=4g` (it holds 1.7 GB now plus about 0.7 GB): update an existing fstab line for `/var/lib/chapter-and-verse-ram` to `size=4g` idempotently and remount with `mount -o remount,size=4g` when mounted. Document in `deploy/README.md`.
- R6 Container start path test (the 21 Nov incident lesson): a test builds a data dir in tmp with the fixture store, a small dense index built from the fixture store's concept docs (any vectors of the right shape), and a models dir with a tiny valid model or the real `bge-small-en-v1.5` if present (skip otherwise), runs `fetch_artefacts.py --verify-only` on it, then `build_runtime` with `DENSE_DIR`/`DENSE_MODEL_DIR` pointing into it and no repo artefacts consulted; startup succeeds and logs dense on. A tampered `vectors.i8` makes fetch verification fail (exit 1).
- R7 Dry run on the real data: `uv run python build/publish_dataset.py --store artefacts/store` with `LEGAL_DATA_ROOT` defaulting as the script does (pass `--data ~/Code/legal-rag-router/data`), and report the file list and total size.
