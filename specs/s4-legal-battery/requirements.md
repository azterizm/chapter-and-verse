# S4.1 Legal battery and gate (F5): requirements

The user's legal tests were ad hoc. We need a fixed battery of instrument-bound questions, run on every release, at two levels. Today (reproduced 24 Nov, no model): "What is the limitation period for bringing a claim in tort under the Limitation Act 1980?" binds `uk/ukpga/1980/58` and the passages sent to the model are s.14A(5), s.21(2), s.25(1), s.28A(1), s.32(1), s.33(6A), Sch 3 para 8, Sch 4: s.2 is missing. "Quote the exact statutory wording of section 172(1)(a) to (d) of the Companies Act 2006." binds `s172/1/a` only. This battery must FAIL those rows today (that is its purpose); do not fix the engine.

- R1 Battery file `batteries/legal/legal.jsonl`, one JSON object per line: `id`, `split` (`dev` or `test`), `question`, `instrument` (store coordinate), `must_reach` (list of section or paragraph coordinates; a row passes retrieval when, for EACH item, some window sent to the model has that coordinate or a descendant of it), `should_reach` (same, reported but not scored), `answer_checks` (object or null, R4), `note`. Rows L01 to L40 are listed in `rows.md` in this spec dir with the instrument title and the section label; resolve each to the store coordinate yourself (use the router and `store.instrument`/`store.get`; regnal-year Acts have five parts). For each row confirm the gold section exists in the store, is in force, and its heading or text is about the question. If a gold looks wrong (repealed, renumbered, prospective, wrong section), do NOT change it: list it in your summary with the evidence and leave the row with `"note": "CHECK: ..."`.
- R2 Seal: `batteries/legal/SEAL.json` with the sha256 of the canonical bytes of the test rows (sorted by id, `canonical_json` from `chapterverse.contracts`) and the row count per split. The gate refuses `--split test` unless `--sealed-test` is passed AND the seal matches.
- R3 Retrieval gate `uv run python -m eval.legal_gate --split dev [--sealed-test] [--out DIR]`: builds the pipeline exactly as `eval/run.py` does (real router index, real store, `NoModelRotation`, no network), runs each row's question through `Pipeline.run`, reads the `route` event and the `sources` event, and reports per row: route status, bound coordinates, windows sent (coordinates), pass or fail with the missing `must_reach` items, and `should_reach` hits. Totals: rows passed, must_reach recall (items reached / items), should_reach recall. Writes `legal-gate.json` and a short `legal-gate.md` to `--out` (default a temp dir under the scratch). Read the data paths as defaults inside the module the way other eval modules do (`LEGAL_DATA_ROOT` default `~/Code/legal-rag-router/data`, `STORE_DIR` default `artefacts/store`); add `--dense-dir` and `--models-dir` options wired as `eval/discovery_gate.py` does (dense may be used by later retrieval work).
- R4 Answer rubric `uv run python -m eval.legal_gate --answers FILE.jsonl`: FILE holds recorded answers, one object per line `{"id": row id, "events": [the SSE events of one /api/ask answer as JSON objects]}`. For rows with `answer_checks`, check: `required_citations` (each listed coordinate, or a descendant, is cited by some sentence's citations), `credit_citations` (reported, not scored), `forbidden_phrases` (case-insensitive substrings no sentence may contain; default list: "provided passages", "the passages", "passages provided", "provisions provided", "the text provided", "the excerpt"), `max_abstentions` (default 1: sentences equal to the policy refusal text, read the text from `chapterverse.audit.policy`, not hard-coded), `no_citations_on_abstention` (true: an abstention sentence has no citations), `no_duplicate_sentences` (true). Anything not a pass is a fail. Also a recorder `--record --target local|live --pace SECONDS` that sends each row with `answer_checks` (or `--all`) to the engine and writes FILE: reuse the HTTP client, headers and pacing of `eval/probes_gate.py` (import it, do not copy it). You must NOT run `--record` (it spends provider quota); test it with a fake transport.
- R5 Tests `tests/test_legal_gate.py`: battery file validates (ids unique, splits only dev/test, 20 and 20, every must_reach inside its instrument), seal check (tampered test row refused), the descendant match rule, the rubric on synthetic event lists (each check passes and fails once), the recorder with a fake transport. Use the fixture store where possible; nothing in tests may need the real store or network.
- R6 Run the dev gate on the real data and report the numbers. Expected today: L01 and L07 fail. Do not run `--split test`.
